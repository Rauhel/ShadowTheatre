# NPC时间触发对话系统使用说明

## 📋 功能概述

NPC时间触发对话系统允许您为NPC对话设置绝对时间触发条件，支持以下两种模式：

### 🚀 立即触发模式（传统模式）
- **触发时间**: -1（默认值）
- **行为**: NPC到达指定路径点时立即显示对话
- **用途**: 适用于基于位置的对话触发

### ⏰ 时间触发模式（新功能）
- **触发时间**: ≥0的数值（故事时间秒数）
- **行为**: NPC到达路径点时将对话加入队列，但只在指定的故事时间才显示
- **用途**: 适用于需要精确时间控制的对话

## 🎯 核心特性

### 优先级系统
- **高优先级** (>0): 可以插队，优先显示
- **普通优先级** (0): 按队列顺序显示  
- **低优先级** (<0): 延后显示

### 智能调度
- 时间触发的对话会等待到指定时间才执行
- 高优先级对话可以中断低优先级对话的显示
- 支持多个对话同时调度，按优先级自动排序

## 🛠️ 使用方法

### 1. 在编辑器中设置

#### 基本设置
1. 选择NPC的数据文件 (NPCData)
2. 在路径配置中找到要设置的对话动作
3. 在"⏰ 时间触发设置"部分进行配置

#### 时间设置选项
- **立即触发**: 设置触发时间为 -1
- **路径开始**: 设置触发时间为 0  
- **路径起始**: 设置为当前路径的起始故事时间
- **自定义时间**: 手动输入具体的故事时间值

#### 优先级设置
- **数值越高优先级越高**
- **0 = 普通优先级**
- **正数 = 高优先级**
- **负数 = 低优先级**

### 2. 代码示例

```csharp
// 创建立即触发的对话
ActionData immediateDialogue = new ActionData
{
    dialogueText = "欢迎来到这里！",
    triggerTime = -1f,  // 立即触发
    priority = 0,       // 普通优先级
    pathPointIndex = 5
};

// 创建时间触发的对话
ActionData timedDialogue = new ActionData
{
    dialogueText = "现在是关键时刻...",
    triggerTime = 120f, // 故事时间120秒时触发
    priority = 5,       // 高优先级
    pathPointIndex = 8
};

// 检查对话触发模式
if (action.IsImmediateTrigger)
{
    Debug.Log("这是立即触发的对话");
}
else if (action.IsTimeTrigger)
{
    Debug.Log($"这是时间触发的对话，将在{action.triggerTime}秒时触发");
}
```

### 3. 运行时监控

启用NPCActionExecutor的`useTimeBasedDialogue`选项后，系统会自动：
- 为NPC添加NPCDialogueScheduler组件
- 在屏幕上显示调试信息（可关闭）
- 显示当前队列状态和下次触发时间

## 📊 调试功能

### 运行时显示信息
- **当前故事时间**: 实时显示
- **即时队列**: 待立即执行的对话数量
- **时间队列**: 等待时间触发的对话数量
- **下次触发**: 最近的时间触发点

### 编辑器中的可视化
- **触发时间按钮**: 颜色编码显示触发模式
  - 白色 = 立即触发
  - 黄色 = 时间触发
- **优先级字段**: 颜色编码显示优先级
  - 绿色 = 高优先级
  - 白色 = 普通优先级  
  - 红色 = 低优先级

## 🔧 系统架构

### 核心组件

#### NPCDialogueScheduler
- 管理时间触发队列
- 检查触发条件
- 按优先级排序
- 提供调试信息

#### NPCActionExecutor (增强版)
- 集成对话调度器
- 支持传统和时间触发两种模式
- 自动处理优先级调度

#### ActionData (扩展版)
- 添加`triggerTime`字段
- 添加`priority`字段
- 提供便捷的判断方法

### 数据流程
```
路径点到达 → 检查触发模式 → 分流处理
├─ 立即触发 → 直接加入执行队列
└─ 时间触发 → 加入时间调度队列 → 时间检查 → 优先级排序 → 执行
```

## ⚠️ 注意事项

### 时间同步
- 系统基于GameState的故事时间系统
- 确保GameState.Instance可用且时间正常更新
- 不同幕的时间可能有偏移，需要考虑幕切换影响

### 性能考虑
- 时间检查在Update中进行，频率较高
- 大量时间触发对话可能影响性能
- 建议合理控制同时调度的对话数量

### 兼容性
- 现有的立即触发对话完全向后兼容
- 默认的triggerTime = -1确保旧数据正常工作
- 编辑器界面渐进式增强，不影响现有工作流

## 🎮 使用场景示例

### 场景1: 分层叙事
```
路径点3: 立即触发 - "我开始了旅程..."
故事时间60秒: 时间触发 - "想起了过去的事情..."  
故事时间120秒: 时间触发 - "时间过得真快..."
```

### 场景2: 紧急插播
```
普通对话: 优先级0 - 正在播放
突发事件: 优先级10 - 立即插队播放
后续对话: 优先级0 - 等待播放
```

### 场景3: 多重触发
```
经过路径点5时:
- 加载3个时间触发对话 (60s, 90s, 120s)
- 系统自动在对应时间点按优先级触发
- 避免了手动管理复杂的时间逻辑
```
